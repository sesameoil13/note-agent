# T25：归档或删除到可恢复的回收站

本票以 NoteWorkspace 为唯一业务入口：`archiveNote`／`unarchiveNote`、`deleteNote`、`restoreNote`、`decideRestoredReminder`，以及只读的 `dailyNotes`、`archivedNotes`、`recycleBin`、`reminderDecisions`。App 的“归档与回收站”页面和笔记详情中的“归档”“移入回收站”按钮都只调用这些方法。批量恢复、永久清除和跨设备删除标记见 T26（docs/development/t26-purge-tombstones.md）。

## 存储

本机 SQLite 新增 `note_disposals(vault, note_id, state, payload)`，每条笔记最多一行：

- `archived`：已归档。笔记仍在 `notes` 中（`archived = true`），只是不进入日常列表；搜索仍能找到并标注“已归档”。笔记文件、提醒、关联都不变。
- `deleted`：在回收站中。`notes`、提醒排程、关联、主题建议、待确认和文本处理任务都看不到这条笔记。payload 保存删除时间、原标题、原路径、删除前的笔记文件全文（含在 Obsidian 中的修改）和阶段 `deleting`／`deleted`。
- `restoring`：恢复进行中，保存选定的恢复路径。

回收站从不自动清空：没有任何按时间清理的逻辑，重启后原样保留。T26 可以在同一张表上增加永久清除（删除行并清理保留副本）、批量恢复（逐项调用同一恢复流程）以及跨设备删除标记（payload 字段或新列），无需迁移已有数据。

## 删除

1. 先读出当前笔记文件全文作为保留副本。有未写入的改名、行动修正、关联修改，或仍在处理中（文档提取、文本处理已排队／发送中／费用待定）时拒绝删除，并说明原因。
2. 在同一事务内写入 `deleted` 行，并把该笔记的有效提醒计划标为 removed、记入待取消列表、标记 `recycled`。随后的提醒核对会取消系统通知。
3. 只删除笔记文件本身（受保护删除；若文件在此期间被其他位置修改，先更新保留副本再删除）。来源文字 `attachments/note-agent/<id>.txt`、附件原件，以及与其他笔记共享的文件都留在笔记库中，直到 T26 的永久清除。
4. 若删除文件失败（例如笔记库暂时不可写），阶段保持 `deleting`；笔记已在回收站、提醒已取消，下次打开工作区或恢复前会再次完成删除。

## 单项恢复

1. 若删除未完成，先完成删除。
2. 同一事务内转为 `restoring`，并处理带 `recycled` 标记的提醒计划：
   - 时间仍在未来：原计划原样恢复（保留稍后提醒、显式时间、时间待确认等信息），使用新的修订号和通知标识，已取消的旧通知不会被复用。
   - 时间已过：不排程；在行动状态中记录 `held`（错过的时间），出现在 `reminderDecisions` 和“过期提醒待决定”区域。
3. 用与采集相同的标题规则选择标题：原标题若已被其他笔记或笔记库中的文件占用，改用“标题 (2)”等编号标题（`titleCollision = true`），绝不覆盖同名笔记。选定的路径先写入数据库再写文件。
4. 用保留副本原样写回笔记文件，然后删除 `note_disposals` 行。写入失败时笔记显示为“写入失败”，“重试写入”与重启都会继续同一恢复流程，仍写回保留副本，不会生成第二份。

恢复后回到日常列表（即使删除前已归档）。

## 过期提醒的决定

`decideRestoredReminder(noteId, actionId, time)`：

- 给出时间：以该时间重新安排（与重新开启的时间选择相同的排程路径）。
- `null`（“不再提醒”）：事项保持未完成，但不再排程。之后明确设置提醒时间、完成或重新开启都会清除此状态。

完成事项也会清除待决定状态。

## 已验证

- `test/recycle_bin_test.dart`（10 项）：真实临时笔记库文件和假通知端口，覆盖归档保留提醒与重启、删除取消提醒并保留来源与不自动清空、未来提醒以新标识恢复、同名不覆盖、过期提醒待决定及重启后的重新安排／不再提醒、共享文件与外部修改不受影响、删除中断后重启完成、关联与主题建议随删除隐藏并随恢复回来、恢复写入失败后重试不产生第二份。
- `test/recycle_bin_ui_test.dart`（1 项）：App 中归档、取消归档、移入回收站、恢复并对过期提醒选择“不再提醒”。
- `flutter analyze`：无问题。

## 尚未验证

- 真实设备上的系统通知取消与恢复后的排程（macOS／Android）未人工验收。
- 另一设备通过 Obsidian Sync 看到删除和恢复的表现；离线副本不复活已删记录（跨设备删除标记）属于 T26。
- 其他笔记指向被删笔记的 `[[链接]]` 不会改写；若恢复时换了编号标题，这些链接仍指向原标题。
- 保留副本只在本机 SQLite 中；本机数据丢失时回收站内容随之丢失（来源文字和附件仍在笔记库）。
