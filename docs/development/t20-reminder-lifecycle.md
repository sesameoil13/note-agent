# T20：从通知完成、延后或重新开启待办

本票以 NoteWorkspace 为公开领域入口。通知操作、App 详情页按钮和测试走同一组方法：`completeAction`、`snoozeReminder`、`reopenAction` 和 `takeReminderInteractions`。没有云端调用或付费请求；跨设备同步属于 T23，Android／Windows 通知按钮属于 T21／T22。

## 生命周期与权威状态

每个已确认行动在本机 SQLite `action_states` 中保存生命周期编号和完成状态，这是提醒排程的唯一依据。笔记中的 `- [x]`／`- [ ]` 只是镜像：完成或重新开启先写本机状态，再通过已有的受保护替换日志改写笔记。笔记在其他位置被修改时不覆盖，完成状态仍然有效、提醒仍然取消，详情页显示“笔记中的勾选尚未写入”，并提供“重试写入勾选”；每次打开工作区也会再尝试一次。

- 完成：取消当前计划和系统通知。同一生命周期内重复完成是幂等的。
- 稍后提醒：只延后当前计划，新计划使用新的通知标识。默认时长 30 分钟，可在“提醒与默认时间”中修改（1–1439 分钟）；详情页可单次选择 10／60／120 分钟或明天此时。已延后的默认计划不再被“预览应用到现有默认提醒”移动。
- 重新开启：仅对已完成事项，必须选择新的提醒时间，生命周期编号加一。之后再明确修改提醒时间时，以新时间为准。
- 删除误提取的行动：沿用已有行动修正，计划立即取消，旧通知上的操作失效。

## 过期与重复的通知操作

通知载荷包含笔记库身份、行动和生命周期编号。workspace 按以下规则处理：

- 来自旧生命周期的“完成”或“稍后提醒”都被忽略，不会关闭已重新开启的事项。
- 已完成事项上的“稍后提醒”被忽略，绝不重新排程。
- “稍后提醒”只接受当前计划的通知标识；同一通知重复投递或已被替换的通知不会再次延后。
- 点按通知正文只打开对应笔记，不改变计划。

第一生命周期的计划保留原有签名，升级后不会因默认时间变化而重排已有提醒。T20 之前已排的系统通知没有按钮和生命周期字段，直到该计划下次改期才带上按钮。

## macOS 适配

`NativeNotifications.swift` 注册 `noteAgent.actionReminder` 类别，含“完成”“稍后提醒”两个后台操作，并只给待办提醒使用。点按结果像既有待确认通知一样先持久存入 UserDefaults，App 启动、回到前台或收到信号时再交给 workspace 处理，因此 App 未运行时的操作不会丢失。
